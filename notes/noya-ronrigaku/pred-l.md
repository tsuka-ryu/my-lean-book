# 述語論理の公理系 L：存在例化（問題53）

## 使う公理系：述語論理の公理系 L

### I 命題論理の公理系 LP の規則

- 規則1［演繹規則 DR］: A を仮定して B が導出されるとき、A という仮定なしに A ⊃ B を導出してよい
- 規則2［前件肯定式 MP］: A, A ⊃ B から B を導出してよい
- 規則3［背理法］: A ⊃ (D ∧ ¬D) から ¬A を導出してよい
- 規則4［二重否定］: ¬¬A から A を導出してよい
- 規則5［結合］: A, B から A ∧ B を導出してよい
- 規則6［分離］:
  1. A ∧ B から A を導出してよい
  2. A ∧ B から B を導出してよい
- 規則7［∨入れ］:
  1. A から A ∨ B を導出してよい
  2. B から A ∨ B を導出してよい
- 規則8［∨取り］: A ∨ B, A ⊃ C, B ⊃ C から C を導出してよい
- 定義: A ≡ B ⇔ (A ⊃ B) ∧ (B ⊃ A)

### II 量化子の規則

- 規則9［全称汎化］: At から ∀xAx を導出してよい（ただし、t は限定なしの項）
- 規則10［全称例化］: ∀xAx から At を導出してよい（t は任意の項）
- 規則11［存在汎化］: At から ∃xAx を導出してよい（t は任意の項）
- 規則12［存在例化］: ∃xAx, Aα ⊃ C から C を導出してよい（① α は新しい項の記号であること、② C には項 α が含まれていないこと）

### 証明の仕方

1. 証明の各行には次のいずれかの論理式が書かれる。
   1. 仮定
   2. 定理（証明済みの論理式）
   3. 証明の先行する行に書かれている論理式と導出規則から導出を認められる論理式
2. 目的の論理式が仮定なしに書き出されたとき、証明は終わる。

### 仮定の扱い

- A を n 行目で仮定するときは A [n]。導出に使った式の仮定はすべて受け継がれ、DR（や背理法）で外した仮定だけが消える。
- [4(α)] は「4行目の仮定で、その仮定に項 α が含まれている」ことを表す。仮定に現れている項は「限定つきの項」で、全称汎化できない（[pred-syntax2.md](pred-syntax2.md)）。

### 量化子の規則の整理

| 記号 | 作る（導入則） | 使う（除去則） |
| --- | --- | --- |
| ∀ | 規則9 全称汎化（t は限定なし） | 規則10 全称例化 |
| ∃ | 規則11 存在汎化 | 規則12 存在例化（α は新しい項、C に α を含まない） |

条件が付いているのは、全称汎化と存在例化の2つ。

### Lean との対応

| 規則 | Lean | やっていること |
| --- | --- | --- |
| 全称汎化（∀ を作る） | `intro t` | 任意の t を取る |
| 全称例化（∀ を使う） | `h t` | 関数に t を渡す |
| 存在汎化（∃ を作る） | `⟨t, h⟩` | 「もの」と「それが条件を満たす証明」のペアを作る |
| 存在例化（∃ を使う） | `obtain ⟨a, h⟩ := h'` | ペアを分解して、新しい a と証明を取り出す |

条件の付いた2つ（全称汎化と存在例化）は、Lean では条件が自動で守られる。

- 全称汎化: ゴールから逆算して先に `intro t` するので、t は何も仮定されていない「限定なしの項」になる。
- 存在例化: `obtain` は必ず新しい名前を作り（①）、その名前をゴールの外に持ち出させない（②）。

## 述語論理のド・モルガンの法則

| | 述語論理 | 命題論理 |
| --- | --- | --- |
| (1) | ¬∃xAx ≡ ∀x¬Ax | ¬(A ∨ B) ≡ ¬A ∧ ¬B |
| (2) | ¬∀xAx ≡ ∃x¬Ax | ¬(A ∧ B) ≡ ¬A ∨ ¬B |

**∀ は大きな ∧、∃ は大きな ∨。** 議論領域が a, b, c の3つだけなら、

- ∀xFx = Fa ∧ Fb ∧ Fc
- ∃xFx = Fa ∨ Fb ∨ Fc

これで確かめると、

```
¬∃xFx = ¬(Fa ∨ Fb ∨ Fc) = ¬Fa ∧ ¬Fb ∧ ¬Fc = ∀x¬Fx    （命題論理のド・モルガン(1)）
¬∀xFx = ¬(Fa ∧ Fb ∧ Fc) = ¬Fa ∨ ¬Fb ∨ ¬Fc = ∃x¬Fx    （命題論理のド・モルガン(2)）
```

- (1) 「F であるものはいない」=「どれも F でない」
- (2) 「全部が F というわけではない」=「F でないものがある」
- 述語論理のド・モルガンは、命題論理のド・モルガンを議論領域のすべてのものに広げたもの。¬ を内側に入れると ∀ と ∃ が入れ替わる（∧ と ∨ が入れ替わるのと同じ）。
- 議論領域が無限だと ∧ や ∨ を無限につなげられないので、これは直感的な説明。正式には規則で証明する。

これまでの問題とのつながり

- 問題52（[pred-syntax2.md](pred-syntax2.md)）の ¬∃xFx ⊃ ∀x¬Fx は (1) の片方向。
- 問題51 の偽定理 ¬∀xFx ⊃ ∀x¬Fx は、(2) の右辺を ∃ ではなく ∀ にしてしまった間違い。
- 問題39(4)（[pred-symbolization.md](pred-symbolization.md)）で ¬∀x(¬Fx ⊃ ¬Gx) を ∃x(¬Fx ∧ Gx) と書き直したのも (2)。

Lean とのつながり（古典論理が要るか）

| | ⇒ | ⇐ |
| --- | --- | --- |
| (1) ¬∃xFx ≡ ∀x¬Fx | 古典論理なし（問題52） | 古典論理なし |
| (2) ¬∀xFx ≡ ∃x¬Fx | **古典論理が必要** | 古典論理なし |

- 命題論理でも、ド・モルガン(2) の ¬(A ∧ B) → ¬A ∨ ¬B だけが古典論理を必要とした（[lean.md](lean.md)）。同じ場所が述語論理でも古典論理を必要とする。
- ¬∀xFx から ∃x¬Fx を言うには、F でないものを具体的に1つ見せる必要がある。でも「全部が F ではない」と分かっただけでは、それがどれかは分からない。だから直観主義論理（Lean の基本の論理）では示せない。

## 存在例化と ∨取り（選言除去）は同じ形

∨取り（規則8）: A ∨ B, A ⊃ C, B ⊃ C から C。**二股の分かれ道**。

```
        ┌─ A の道 ──→ C 村
今ここ ─┤
        └─ B の道 ──→ C 村
```

どちらの道を通るかは分からないが、どちらを通っても C 村に着くので C。

∃xAx = Aa ∨ Ab ∨ Ac ∨ … なので、∃ は**無数の分かれ道**。

```
        ┌─ Aa の道 ──→ C 村
        ├─ Ab の道 ──→ C 村
今ここ ─┼─ Ac の道 ──→ C 村
        └─ …
```

道が無数にあるので、Aa ⊃ C、Ab ⊃ C、… を1本ずつ示すことはできない。そこで**名前も特徴もない道 α を1本選び**、Aα ⊃ C を示す。α について何も特別なことを仮定していないので、その議論はどの道でもそのまま通用する。

| | 分かれ道 | 各道について示すこと | 結論 |
| --- | --- | --- | --- |
| ∨取り | A ∨ B（2本） | A ⊃ C と B ⊃ C（2回） | C |
| 存在例化 | ∃xAx（無数） | Aα ⊃ C（任意の1本で1回） | C |

2つの条件の意味

- ① α は新しい記号: 「任意の道」でなければいけない。知っている a の道だと、「a の道だから C 村に着いた」かもしれず、他の道でも着くとは言えない。
- ② C に α が含まれない: どの道を行っても**同じ C 村**に着く必要がある。行き先が「α 村」のように道によって変わるのでは、「どの道でも C」とは言えない。

Lean でも同じ形

```lean
rcases h with h1 | h2    -- ∨ を使う：2つの場合に分ける
obtain ⟨a, ha⟩ := h      -- ∃ を使う：任意の a の場合を1つ考える
```

どちらも「場合分けして、それぞれでゴール C を示す」操作。∨ は場合が2つ、∃ は「任意の a」の場合が1つ（で全部を代表する）。

全称汎化も同じ考え方（何でもいい t で示せたら、すべての x で言える）。**任意のものについて示せば、すべてについて示したことになる**、という考え方が、∀ を作るときと ∃ を使うときの両方に出てくる。

## 問題

### 問題53

次の定理に対する証明の空欄を埋めよ。

定理 (∀x(Fx ⊃ Gx) ∧ ∃xFx) ⊃ ∃xGx

| 行 | 論理式 | 仮定 | 根拠 |
| --- | --- | --- | --- |
| 1 | ∀x(Fx ⊃ Gx) ∧ ∃xFx | [1] | 仮定 |
| 2 | ∀x(Fx ⊃ Gx) | [1] | 1 と分離 |
| 3 | ∃xFx | [1] | 1 と分離 |
| 4 | Fα | [4(α)] | 仮定 |
| 5 | （イ） | [1] | 2 を α で全称例化 |
| 6 | Gα | [1, 4(α)] | 4, 5 と MP |
| 7 | （ロ） | [1, 4(α)] | 6 と存在汎化 |
| 8 | Fα ⊃ ∃xGx | [1] | 4, 7 と DR |
| 9 | （ハ） | [1] | 3, 8 と存在例化 |
| 10 | (∀x(Fx ⊃ Gx) ∧ ∃xFx) ⊃ ∃xGx | なし | 1, 9 と DR |

- 状態: 本の解答を確認済み

解答（本より）: （イ）Fα ⊃ Gα　（ロ）∃xGx　（ハ）∃xGx

メモ

- 意味: 「すべての F は G で、F であるものがいるなら、G であるものがいる」。例: すべての人間は死ぬ、人間がいる、ゆえに死ぬものがいる。
- （イ）: 2行目 ∀x(Fx ⊃ Gx) を α で全称例化（□ = Fx ⊃ Gx の x を全部 α に）。問題50と同じ形。
- （ロ）: 6行目 Gα を存在汎化して ∃xGx。
- 8行目: DR で仮定 4(α) を外して Fα ⊃ ∃xGx。仮定は [1] だけになる。
- （ハ）: 存在例化「∃xAx, Aα ⊃ C から C」に、3行目 ∃xFx（Ax = Fx）と8行目 Fα ⊃ ∃xGx（C = ∃xGx）を当てはめて ∃xGx。

存在例化の考え方

- ∃xFx は「F であるものが（少なくとも1つ）いる」だが、それが誰かは分からない。
- そこで「それに仮の名前 α を付けて」Fα を仮定し（4行目）、C を導く。導けたら DR で Fα ⊃ C にまとめる（8行目）。
- 「誰であっても、F であるなら C」が示せたので、F であるものがいる以上 C が言える（9行目）。
- 作戦の型: ∃xAx を使いたいときは、**Aα を仮定 → C を導く → DR で Aα ⊃ C → 存在例化で C**。

条件の意味

- ① α は新しい項の記号であること: α は「F であるもの（誰かは知らない）」の仮の名前。すでに使っている a などを使うと、「その a が F である」という根拠のない主張をすることになる。例えば ∃xFx（肉食の動物がいる）から、ウサギ = a について Fa（ウサギは肉食）を仮定して使ってはいけない。
- ② C には項 α が含まれていないこと: α は証明の中だけの仮の名前なので、結論 C に残ってはいけない。例えば C = Gα だと「（誰か分からない）α は G である」という意味不明な結論になる。問題53では C = ∃xGx で、α は含まれていない（Gα を存在汎化して α を消したのはこのため）。

```
∃xFx（3行目） ─────────────────────────────┐
仮に Fα としよう（α は新しい名前）──────┐ [4(α)] │
│ Fα ⊃ Gα（全称例化）                  │        │
│ Gα（MP）                             │        │
│ ∃xGx（存在汎化。ここで α が消える）     │        │
└──────────────────────────────────────┘        │
Fα ⊃ ∃xGx（DR）                                  │
∃xGx（存在例化：3行目と8行目から）  ◀────────────┘
```

Lean で書くと（動作確認済み、2026-10-12）

```lean
example (α : Type) (F G : α → Prop) : (∀ x, F x → G x) ∧ (∃ x, F x) → ∃ x, G x := by
  intro h                  -- (1) 仮定
  have h2 := h.1           -- (2) 分離
  have h3 := h.2           -- (3) 分離
  obtain ⟨a, h4⟩ := h3     -- 存在例化：新しい a と (4) Fa を取り出す
  have h5 := h2 a          -- (5) 全称例化：Fa → Ga
  have h6 := h5 h4         -- (6) MP：Ga
  exact ⟨a, h6⟩            -- (7) 存在汎化：∃xGx
```

- 存在例化は `obtain ⟨a, h4⟩ := h3`。∃ の証明（ペア）を分解して、新しい名前 a と、`h4 : F a` を取り出す。
- 条件①は自動: obtain は必ず新しい名前を作る。
- 条件②も自動: Lean は a をゴールの外に持ち出させない（ゴール `∃ x, G x` には a が含まれない）。
- 本の 8行目（DR）と 9行目（存在例化）は、Lean では obtain 1つにまとまっている。

Lean のコードの読み方

名前の注意: コードの `α` は議論領域の型（本の D）。本の証明に出てくる新しい項 α は、コードでは `a`。同じ記号だが別物。

`(∃ x, F x)` のカッコは必要。カッコがないと `∃ x,` が右端の `→ ∃ x, G x` までかかってしまう。

各ステップ後の Infoview

```
-- have h2, h3 の後
h2 : ∀ x, F x → G x
h3 : ∃ x, F x
⊢ ∃ x, G x

-- obtain ⟨a, h4⟩ := h3 の後
h2 : ∀ x, F x → G x
a  : α
h4 : F a
⊢ ∃ x, G x

-- have h5, h6 の後
h5 : F a → G a
h6 : G a
⊢ ∃ x, G x
```

- `obtain ⟨a, h4⟩ := h3`: ∃ の証明は「もの」と「証明」のペア。obtain はそれを分解して取り出す（`⟨t, h⟩` でペアを作るのの逆）。`a : α` は中身の分からない「F であるもの」に付けた新しい名前、`h4 : F a` は a が F である証明。
- `h2 a`: 全称例化。∀ の関数に a を渡して `F a → G a`。
- `h5 h4`: MP。→ の関数に F a の証明を渡して `G a`。
- `⟨a, h6⟩`: 存在汎化。a と G a の証明をペアにして `∃ x, G x`。ゴールそのものなので exact で完了。

本と Lean の対応

| 本 | Lean | やっていること |
| --- | --- | --- |
| 1行目 仮定、10行目 DR | `intro h` | 左側を仮定 |
| 2, 3行目 分離 | `h.1`, `h.2` | ∧ を分ける |
| 4行目 仮定、8行目 DR、9行目 存在例化 | `obtain ⟨a, h4⟩ := h3` | ∃ のペアを分解して、新しい a と F a を取り出す |
| 5行目 全称例化 | `h2 a` | ∀ に a を渡す |
| 6行目 MP | `h5 h4` | → に F a の証明を渡す |
| 7行目 存在汎化 | `⟨a, h6⟩` | a と G a の証明をペアにする |

∃ の扱い: 作る（存在汎化）は `⟨もの, 証明⟩` でペアを作る、使う（存在例化）は `obtain ⟨もの, 証明⟩ := h` でペアを分解する。
