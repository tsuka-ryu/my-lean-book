# 命題論理と Lean の対応

本の公理系（主に LP）で手でやった証明が、Lean ではどうなるかのまとめ。

## 使う公理系：命題論理の公理系 LP

詳しくは [lp.md](lp.md)。

- 規則1［演繹規則 DR］: A を仮定して B が導出されるとき、A という仮定なしに A ⊃ B を導出してよい
- 規則2［前件肯定式 MP］: A, A ⊃ B から B を導出してよい
- 規則3［背理法］: A ⊃ (D ∧ ¬D) から ¬A を導出してよい
- 規則4［二重否定］: ¬¬A から A を導出してよい
- 規則5［結合］: A, B から A ∧ B を導出してよい
- 規則6［分離］: A ∧ B から A を、A ∧ B から B を導出してよい
- 規則7［∨入れ］: A から A ∨ B を、B から A ∨ B を導出してよい
- 規則8［∨取り］: A ∨ B, A ⊃ C, B ⊃ C から C を導出してよい
- 定義: A ≡ B は (A ⊃ B) ∧ (B ⊃ A) の略記

## 1. 規則と Lean のタクティクの対応

| LP の規則 | Lean のタクティク・項 |
| --- | --- |
| 規則1 演繹規則（仮定を外す） | `intro h` |
| 規則2 前件肯定式 | `apply h` ／ `h x`（関数適用） |
| 規則3 背理法 | ¬A を示すとき `intro h` して `False` を示す |
| 規則4 二重否定 | `by_contra`（古典論理） |
| 規則5 結合 | `constructor` ／ `⟨h1, h2⟩` |
| 規則6 分離 | `h.1` ／ `h.2` ／ `obtain ⟨h1, h2⟩ := h` |
| 規則7 ∨入れ | `left` ／ `right` |
| 規則8 ∨取り | `cases h` ／ `rcases h with h1 \| h2` |
| ≡ | `↔`（`constructor` で両方向に分ける） |
| ⊃ | `→` |

Lean の画面に出る仮定の一覧（文脈）は、本の [ ] の番号を自動で管理してくれているもの。`intro h` で `h : A` が現れるのが、本の「A [n]」（箱を開ける）にあたる。

## 2. Lean では ¬A は「A → False」

本では矛盾を D ∧ ¬D の形で作ったが、Lean では ¬A は A → False の略記で、矛盾は `False` そのもの。そのため証明が短くなる。

例題7（本では6行）

```lean
example (A : Prop) : A → ¬¬A := by
  intro h1      -- [1] A を仮定
  intro h2      -- [2] ¬A を仮定（¬¬A = ¬A → False だから intro できる）
  exact h2 h1   -- ¬A に A を渡すと False
```

問題24（本では9行）

```lean
example (A B : Prop) : (A → ¬B) → (B → ¬A) := by
  intro h1 h2 h3   -- 箱を3つ開ける（A ⊃ ¬B, B, A）
  exact h1 h3 h2   -- h1 h3 : ¬B、それに h2 : B を渡すと False
```

`intro` を3回するのが、本の「箱が3重」と対応している。

## 3. 古典論理と直観主義論理

- Lean の基本の論理は直観主義論理で、二重否定除去（¬¬A → A）や排中律（A ∨ ¬A）は入っていない。
- 使うには `Classical` が必要（`by_contra`, `Classical.em` など）。
- LP の規則4（二重否定）がちょうどこの境目。サンプル2には規則4がなく、A ⊃ ¬¬A（例題7）は示せたが、逆向きの ¬¬A ⊃ A は示せなかった。Lean でも同じ。

p.70 の諸定理の分類（⇒/⇐ は ≡ の左→右／右→左）

| 古典論理なしで証明できる | 古典論理が必要 |
| --- | --- |
| 定理1, 3, 4, 5, 6, 7, 8, 11, 12 | 定理2 排中律 |
| 定理9(1) ド・モルガン（両方向） | 定理9(2) の ⇒（¬(A ∧ B) → ¬A ∨ ¬B） |
| 定理9(2) の ⇐ | 定理10 の ⇐（(A → B) → ¬A ∨ B） |
| 定理10 の ⇒ | 対偶の逆（(¬B → ¬A) → (A → B)） |

左の列は Lean で `Classical` なしに型検査が通ることを確認済み（2026-10-12）。

Lean で詰まったら「これは古典論理が要る式か？」を疑い、要るなら `by_contra` などを使う。

## 4. 証明はプログラム（カリー＝ハワード対応）

| 論理 | プログラム |
| --- | --- |
| A ⊃ B の証明 | A を受け取って B を返す関数 |
| 仮定を置く | 引数を受け取る |
| 規則1（仮定を外す） | 関数を作る（`fun h => ...`） |
| 規則2（前件肯定式） | 関数に引数を渡す |
| A ∧ B の証明 | 組（ペア） |

問題24の証明は、項で書くと関数そのもの。

```lean
example (A B : Prop) : (A → ¬B) → (B → ¬A) := fun h1 h2 h3 => h1 h3 h2
```

## 5. ゴールから逆算（本は作った順、Lean は考えた順）

証明の進め方には2つの向きがある。

- 前向き（順方向）: 手元にあるものから新しいものを作っていく（材料 → 切る → 炒める → カレー）
- 後ろ向き（逆算）: 作りたいものから「それには何が必要か」をさかのぼる（カレーを作りたい → 炒めればいい → 切ればいい → 材料はある）

本の証明は1行目から順に並んでいるので前向きに見えるが、作戦（「ゴールは ⊃ だから左を仮定」など）は逆算。本では逆算を頭の中でやってから、前向きに書き直している。そのため上から読むと「なぜここでこの仮定を置くのか」が分からず、トレースしにくい。

Lean の画面には常に `⊢ ゴール` が出ていて、多くのタクティクは「今のゴールを、もっと簡単なゴールに置き換える」操作。1つ進むたびにゴールが小さくなり、手元の材料でゴールそのものが作れたら `exact` で終わり。

| 種類 | タクティク | 動き |
| --- | --- | --- |
| ゴールを変える（逆算） | `intro`, `apply`, `constructor` など | ゴールを小さくする |
| 手元を増やす（前向き） | `have`, `obtain` など | ゴールはそのまま、仮定を増やす |

実際の証明ではこの2つを行き来し、2つが出会ったところで `exact`。

本では DR が最後なのに Lean では intro が最初に来るのは、**同じ証明を、作った順に書くか（本）、考えた順に書くか（Lean）の違い**。

読み方のコツ

- 本の証明は**下から読む**: 最後の行から上へ、「この行を出すために何が必要だったか」とたどると作戦が見える。
- Lean の証明は **Infoview の `⊢` を見ながら読む**: タクティクの意味より、ゴールがどう小さくなったかが大事。

## 補足

- 構文論と意味論: 本でやった公理系は構文論（記号の操作）。真理値表は意味論。この2つが一致することが健全性・完全性。「LP が本当に完全かどうかはメタ論理で証明すべき課題」はこの話。Lean で論理式を `inductive` で定義すれば、完全性定理そのものも形式化できる。
- 記号の結合の強さ: Lean では `¬` > `∧` > `∨` > `→` の順に強く結びつき、`→` は右結合（`A → B → C` は `A → (B → C)`）。本の式を Lean に写すときはカッコに注意。
